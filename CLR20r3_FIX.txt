┌────────────────────────────────────────────────────────────┐
│  🔍 QU'EST-CE QUE L'ERREUR CLR20r3 ?                      │
└────────────────────────────────────────────────────────────┘

CLR20r3 = Common Language Runtime version 2.0, erreur type 3

C'est une exception non gérée qui se produit AVANT que votre 
interface ne s'affiche, généralement au moment de l'initialisation 
des composants.

Causes typiques :
❌ NullReferenceException lors de l'initialisation
❌ Exception dans le constructeur du formulaire
❌ Problème de chargement des références (DLL manquantes)
❌ Erreur dans InitializeComponent()
❌ Service WCF mal configuré

┌────────────────────────────────────────────────────────────┐
│  🐛 PROBLÈME IDENTIFIÉ DANS VOTRE CODE                    │
└────────────────────────────────────────────────────────────┘

AVANT (ligne 22 dans Form1.cs) :
────────────────────────────────
```csharp
public partial class Form1 : Form
{
    public Form1()
    {
        InitializeComponent();
    }
    // ❌ PROBLÈME ICI : Initialisation APRÈS le constructeur
    ServiceSenAgriculture.Service1Client service = 
        new ServiceSenAgriculture.Service1Client();
}
```

❌ Pourquoi c'est un problème :
   1. L'ordre d'exécution n'est pas garanti
   2. Si la création du service échoue, l'exception n'est pas gérée
   3. Le service peut être utilisé avant d'être initialisé
   4. Pas de try-catch pour capturer les erreurs

┌────────────────────────────────────────────────────────────┐
│  ✅ SOLUTION APPLIQUÉE                                     │
└────────────────────────────────────────────────────────────┘

APRÈS (corrigé) :
─────────────────
```csharp
public partial class Form1 : Form
{
    // ✅ Déclaration seulement (pas d'initialisation)
    private ServiceSenAgriculture.Service1Client service;

    public Form1()
    {
        InitializeComponent();

        // ✅ Initialisation DANS le constructeur avec try-catch
        try
        {
            service = new ServiceSenAgriculture.Service1Client();

            // Configuration des timeouts
            service.Endpoint.Binding.SendTimeout = TimeSpan.FromMinutes(5);
            service.Endpoint.Binding.ReceiveTimeout = TimeSpan.FromMinutes(5);
            service.Endpoint.Binding.OpenTimeout = TimeSpan.FromMinutes(5);
            service.Endpoint.Binding.CloseTimeout = TimeSpan.FromMinutes(5);

            System.Diagnostics.Debug.WriteLine(
                $"Service initialisé avec succès. URL: {service.Endpoint.Address.Uri}"
            );
        }
        catch (Exception ex)
        {
            System.Diagnostics.Debug.WriteLine(
                $"ERREUR lors de l'initialisation du service: {ex.Message}"
            );
            MessageBox.Show(
                $"Erreur lors de l'initialisation du service WCF.\n\n" +
                $"Détails : {ex.Message}\n\n" +
                "Vérifiez que le fichier App.config est correctement configuré.",
                "Erreur d'initialisation",
                MessageBoxButtons.OK,
                MessageBoxIcon.Error
            );
            service = null;
        }
    }
}
```

✅ Avantages de cette solution :
   1. ✓ Ordre d'exécution garanti (dans le constructeur)
   2. ✓ Exception capturée et affichée à l'utilisateur
   3. ✓ service = null si échec (empêche NullRef plus tard)
   4. ✓ Logs de débogage pour diagnostic
   5. ✓ Configuration des timeouts immédiate
